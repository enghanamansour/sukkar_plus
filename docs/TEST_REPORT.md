# Test report

Results actually obtained while building the project (28 Oct 2026). Passing automated tests are **not** clinical validation.

## Environment

The build sandbox had Dart 3.13.7 and Node 22.23 but **no Flutter engine and no pub.dev access**. Therefore:

* `sukkar_core` tests ran with a minimal stand-in for `package:test` (`tool/offline_test_shim`, run by `tool/run_core_tests_offline.sh`). On a normal machine use `dart test`.
* The Flutter app was **statically analysed** against the real Flutter **3.47.8** framework sources and the real release sources of riverpod 3.4.3, go_router 18.1.1, pdfrx 2.10.1, file_picker 13.3.0, pdf/printing 5.15.1 and supabase_flutter 2.18.3 (cloned from GitHub), but it was **not run on a device or emulator**, and widget tests were **not executed**.

## Additional checks performed locally (data not in the repository)

* **Real Omnipod Discover report (supplied):** PDFium text → parser: 12 of 12 fields found, report period (90 days) and sensor-data window (56 days) parsed, all 6 arithmetic checks pass. Printed connected-sensor time is 62 % (< 70 %), so the rule engine returns "نحتاج بيانات إضافية" with all target rules "not assessable".
* **AZT1D (25 subject files):** all files import (both column variants), bands sum to 100 %, 0 skipped rows, 5,288 exact duplicate rows dropped and 501 conflicting duplicates flagged.
* **PDF round trip:** the demo report PDF generated by the app's builder (pdf package + IBM Plex Sans Arabic) passes validation; PDFium extracts it and the parser finds 12/12 fields with all checks passing. The visit-summary PDF (3 pages) was rendered and inspected; Arabic shaping, RTL layout, dates and change wording were corrected after inspection.
* **Demo narrative:** the steps in DEMO_SCRIPT.md were replayed against the core logic (alignment before/after entering HbA1c, rule outcome of the upload, period comparison).
* **Palette:** chart colours pass the dataviz validator (lightness, chroma, CVD separation, normal-vision floor, contrast).

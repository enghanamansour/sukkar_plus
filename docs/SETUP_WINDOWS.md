# Setup on Windows

## Versions

| Tool | Version used / required | Needed for |
|------|------------------------|-----------|
| Flutter | **3.47.8 stable** (ships Dart 3.13) — `pdfrx 2.10.1` needs Flutter ≥ 3.47 and Dart ≥ 3.13 | the app |
| Dart | 3.13 (bundled with Flutter) | core package tests |
| Git | any recent | cloning |
| Android Studio + an emulator (API 34+) **or** Visual Studio 2022 with "Desktop development with C++" | latest | Android or Windows desktop target |
| Node.js | ≥ 22.6 (tested with 22.23) | backend tests only |
| Supabase CLI | latest (`npm i -g supabase` or Scoop) | live backend only |

Enable **Developer Mode** in Windows settings (Flutter plugins need symlinks). The Windows build of `pdfrx` downloads PDFium during the first CMake build, so the first `flutter run -d windows` needs internet access.

## 1. Get the code and run the core tests

```powershell
git clone https://github.com/enghanamansour/sukkar_plus.git
cd sukkar_plus\packages\sukkar_core
dart pub get
dart test
```

## 2. Create the platform folders and run the app in demo mode

The repository contains the Flutter `lib/`, assets and tests; platform folders are generated by Flutter (it will not overwrite existing files).

```powershell
cd ..\..\app
flutter create . --platforms=android,windows --project-name sukkar_plus --org sa.sukkarplus
flutter pub get
flutter analyze
flutter test
```

Run (demo mode is the default when no Supabase settings are compiled in):

```powershell
flutter run -d windows
# or, with an Android emulator:
flutter emulators                      # list
flutter emulators --launch <emulator_id>
flutter devices                        # note the device id, e.g. emulator-5554
flutter run -d emulator-5554
```

If the Android build reports a `minSdk` error, set `minSdk = 24` in `android/app/build.gradle.kts`.

You can also run `tool\setup_windows.ps1` from the repository root, which performs steps 1–2.

## 3. Live mode (optional): Supabase

1. Create a project at supabase.com. Note the **Project URL** and **publishable key** (Project Settings → API; older projects call it the anon key). These two values are public by design and protected by RLS.
2. From the repository root:

```powershell
npm i -g supabase
supabase login
supabase link --project-ref <your-project-ref>
supabase db push                      # applies supabase/migrations
supabase functions deploy extract-report explain followup-dispatch
```

3. Create users in **Authentication → Users** (email + password). For a quick demo, turn off email confirmation or confirm the users manually.
4. Give one user the reviewer role (users can never change their own role):

```sql
update public.profiles set role = 'reviewer'
where id = (select id from auth.users where email = 'reviewer@example.com');
```

   Or create `demo-patient@example.com` and `demo-reviewer@example.com` and run `supabase/seed.sql` in the SQL editor to load synthetic data.

5. Copy `app/dart_defines.example.json` to `app/dart_defines.json`, fill in the URL and publishable key, then:

```powershell
cd app
flutter run -d windows --dart-define-from-file=dart_defines.json
```

On Android, add `<uses-permission android:name="android.permission.INTERNET"/>` to `android/app/src/main/AndroidManifest.xml` for release builds.

## 4. Gemini (optional, server-side only)

1. Create an API key in Google AI Studio.
2. `supabase secrets set GEMINI_API_KEY=<key> GEMINI_MODEL=gemini-3.8-flash`
3. In the app, open the consent screen and tick the separate external-AI consent; on the upload screen enable "مقارنة القيم مع استخراج Gemini".

Without the secret, `extract-report` and `explain` return `503 ai_not_configured`; the app shows that the local reader/template was used. The functions call `generateContent`, which Google documents as legacy but fully supported; migrating to the newer Interactions API only requires changing `_shared/gemini.ts`. Review Google's data-use terms for your account tier before sending real health data.

## 5. Make.com (optional, server-side only)

See [make/README.md](../make/README.md), then:

```powershell
supabase secrets set MAKE_WEBHOOK_URL=<https://hook.….make.com/…> MAKE_WEBHOOK_API_KEY=<key> SUKKAR_ENVIRONMENT=demo
```

Without these, `followup-dispatch` records a labelled `local_mock` event; nothing leaves the server.
